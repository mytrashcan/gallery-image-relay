# Production hardening review — 2026-09-05

Baseline: `15f2847d019c994d9c885fe2d4a140808aade93e`. Changes are on the local `production-hardening` branch. Source, tests, configuration, CI, frontend, dashboard, Linux units and macOS/OCI scripts were reviewed before implementation. No remote deployment or external message delivery was performed. This report separates application verification from infrastructure assumptions.

## 1. Architecture overview

`launcher.py` runs independent `run_gallery.py` subprocesses, with separate DC/Arca concurrency budgets, rotation and crash restart backoff. A source-specific bot owns its crawler, image handler, delivery pipeline, HTTP resources and one SQLite archive connection. Crawler HTML polling runs in blocking workers; bots coordinate asynchronous Discord/Telegram delivery. DC selects one image per post; Arca selects up to four and batches Discord attachments. `MediaPipeline` aggregates explicit destination outcomes. `MessageSender` owns transport operations, including 413 recompression/fallback. `GalleryClient` drains a bounded per-bot RAM queue into authenticated FastAPI ingest. One `MemoryGalleryStore` owns original/thumbnail bytes and metadata, with item, byte and TTL bounds.

Durable state is only `(source, gallery_name, delivery_key, delivered_at)`: post IDs, image hashes and destination receipts. Pending hash reservations, upload queues, rate buckets, web content and default honeypot events are volatile. Source sites/CDNs, Discord, Telegram and optional Cloudflare/SSH/SOCKS infrastructure are separate trust boundaries. The combined runner now supervises web and bot tasks in one event loop; the multi-process architecture is preserved.

## 2. Critical issues found and selected plan

Priorities describe operational impact, not CVSS severity.

- **P0 — partial delivery permanently forgotten.** `DeliveryResult.acknowledged` used any-success semantics. DC could archive a post after Discord succeeded and Telegram failed; Arca could archive despite another failed channel/batch. Selected fix: require every eligible durable destination, record destination/media receipts as soon as confirmed, and retry only missing receipts. This intentionally supersedes the older any-success design document because it can lose requested deliveries.
- **P1 — cancellation outlives resource ownership.** Cancelling `to_thread` does not terminate its worker; shutdown could close a session/archive or free a concurrency slot while work was still running. Arca reservations could survive preparation/delivery errors. Selected fix: shield/join blocking work, clean sibling tasks and reservations, close pooled sessions and join supervised runtime tasks.
- **P1 — aggregate resource bounds incomplete.** Animated image checks only bounded a frame, compression retained many full-size frames, queue size counted items but not bytes, ingest/verification waiters and rate-map keys could accumulate, idle TTL relied on traffic, honeypot JSONL grew without bound. Selected fix: aggregate frame/pixel budgets, downsize retained GIF frames, queue byte admission, bounded active request slots, body deadlines, hard bucket caps, idle expiry and bounded default RAM diagnostics.
- **P1 — proxy-header omission/spoofing affected public controls.** Feed gating depended on `cf-connecting-ip`; missing origin secret trusted arbitrary supplied IPs. Selected fix: enforce Turnstile independently, protect image/like paths too, and trust forwarded IP only with a valid origin secret.
- **P1 — credential/content metadata could persist in logs.** Source titles/filenames/URLs and HTTPX Telegram token-bearing URLs were loggable. Selected fix: remove source metadata from call sites, filter configured credentials/transport URLs and exception text, keep safe source/gallery/post identifiers, and remove unlimited launcher append logs.
- **P1 — lifecycle and deployment recovery gaps.** Combined DC/web mode omitted gallery identity and wrapped a sender path the batch pipeline did not use; daemon web thread was not joined. Deployment replaced code/dependencies in place with no recovery path. Selected fix: explicit supervised combined runner and staged dependency promotion with rollback of code/venv/units.
- **P2 — validation and efficiency inconsistencies.** Different dotenv precedence/CWD behavior, unvalidated gallery settings, implicit redirect following, unbounded HTML response buffering, unreused Arca image sessions, and overlapping frontend polling. Selected fix: common configuration/URL rules, bounded page fetch, fixed session pool, oldest-first selection within the visible page, and nonoverlapping polling with backoff.
- **P3 — documentation/tooling drift.** Documented image count, TTL, supported CI versions, private tunnel file and old acknowledgement contract did not match source. Selected fix: correct documentation, add constrained dependency snapshot, import check and Windows/Linux Python 3.11/3.12 CI matrix. No cosmetic-only rewrite or runtime dependency was added.

## 3. Changes implemented

`MediaPipeline._record()` writes collision-free receipt keys through `DeliveryArchive.add_many()`. Receipts survive restart; successful fallback items are recorded before the next await, so cancellation of a later 413 fallback item cannot erase known progress. `media_acknowledged()` gates each hash independently; bots mark a post only after all required outcomes and source preparation are resolved. The existing SQLite table stays compatible; an age index supports explicit pruning and FULL synchronous commits strengthen receipt durability.

`run_blocking()` retains ownership until its OS thread finishes, including repeated cancellation and worker failure. Both bot shutdown paths close request pools, sender resources, web queue and archive. Arca uses one reusable Session per concurrency slot and releases reserved hashes on failed preparation, cancelled siblings and delivery exit. `run_until_signal()` lets SIGTERM reach this cleanup; launcher children receive a shared bounded stop deadline and force-kill/reap fallback. Leader locking supports Unix and Windows; an actual second-process exclusion test passes.

The combined runner uses `supervise()` to wait for web readiness and stop both services on cancellation/failure. Both DC and Arca now use their normal pipeline and receive gallery identity. Launcher spawns use absolute script paths and an explicit working directory; configuration errors fail early.

## 4. Security improvements

`url_policy.py`, `page_fetch.py` and `media_download.py` reject malformed/untrusted source destinations and revalidate each redirect before requesting it. Pages have a 4 MiB decompressed-stream bound; media retain encoded-byte and aggregate-attempt limits with a request-chain deadline. Ingest POST redirects are refused so publication tokens are not forwarded. Arca proxy sessions ignore ambient proxy variables; the configured proxy applies consistently to HTML and media.

`ImageHandler.validate_image_data()` bounds dimensions, animation frames and cumulative decoded canvas pixels. GIF compression retains reduced frames and returns the actual encoded size after rewinding. Web image decoding remains capped independently and thumbnail bytes count against store capacity. No application image-byte filesystem/tempfile path was introduced.

`web_app` enforces Turnstile without relying on the presence of a proxy header; images and likes share the gate and maintenance behavior. Invalid Unicode cookies return false; invalid auth stays 401. Verification and ingest admission are bounded before body/decoder work, with body timeouts and overload responses. IP maps have a hard capacity and unauthenticated proxy headers no longer create arbitrary identities.

`logging_policy.PrivacyFilter` redacts configured tokens, HTTP/SOCKS URLs and exception text before root handlers persist logs. A real HTTPX request over MockTransport verifies token-bearing URL redaction without a network request. Honeypot logging defaults to a bounded RAM ring; disk recording requires opt-in and rotates. Existing DOM textContent construction, fixed static-file routes, parameterized SQL, no-store image/feed headers and list-based subprocess arguments were preserved.

The original static security scan reported four source findings (two medium, two low); its canonical artifacts describe the baseline, not the repaired worktree. It explicitly has partial security coverage for external/dependency/infrastructure questions. The new regression evidence addresses the code paths above; this is not a claim that production infrastructure or all transitive dependency behavior has been security-certified.

## 5. Reliability improvements

Network/decoder work retains concurrency ownership through cancellation. Permanent 404/410 detail pages are distinguishable from access failures and parser drift; unavailable HTML does not masquerade as a permanently rejected image. Both sources now select oldest eligible posts on the current page, reducing newest-first starvation. Failed destinations remain retryable while successful ones are skipped from durable receipts.

The launcher preserves process isolation, independent source rotation and restart backoff. SIGTERM during readiness exits its wait. Web restart no longer stops the launcher through a systemd Requires relationship. Systemd grants a bounded graceful stop, disables swap/core limits for both services and writes journal logs. macOS plist generation uses `plistlib`, venv selection is explicit, broad `pkill` is removed, and bootstrap failures are visible. OCI deployment stages dependencies, verifies configuration/imports before stopping services and retains prior release material for rollback. See [deployment.md](deployment.md) for exact recovery and host-validation limits.

## 6. Performance improvements

Arca reuses a bounded pool of HTTP connections. Source HTML is streamed under a size bound rather than materialized unboundedly. GIF retained frames are resized before accumulation. The web queue defaults to 32 MiB per crawler including its in-flight request, alongside its existing 20-item cap. Default web image storage remains 256 MiB including thumbnails; the hash-recency map is capped at twice the item count. A one-second sweeper reclaims expired images even without requests.

Frontend polling uses one outstanding fetch, a ten-second abort deadline, exponential error backoff to sixty seconds, and pauses while hidden. No-store originals are no longer prefetched and then fetched again for display. No database/image-byte storage or frontend framework was added. These changes target measured/code-proven amplification paths; no production throughput benchmark is claimed.

## 9. Remaining risks / recommended future work

1. **Bounded catch-up and fair retry scheduling (P1 follow-up).** There is still no historical pagination. Busy boards, long outages, source rotation and a repeatedly failing oldest DC post can lose or delay visible-page posts. Add an explicit maximum-page/time/age catch-up policy with real captured pagination fixtures and per-post retry backoff; do not silently crawl unlimited history or weaken moderation windows. DC's one-image and Arca's four-image cap remain intentional current behavior.
2. **Uncertain remote acknowledgements.** External sends and SQLite commits cannot form one transaction. A timeout or crash after remote acceptance can duplicate a message. Existing archives cannot reconstruct destinations forgotten by the old any-success policy; newly added destinations do not automatically replay historical posts. Retention/pruning must be deliberate.
3. **Infrastructure verification.** Run a staging systemd rollback drill, launchctl stop/restart drill, Cloudflare ingress/header checks and residential SOCKS outage test before production promotion. The private live Cloudflare/autossh configs were absent from the repository. No live credentials or accounts were used. Promotion is multi-step; power loss can require manual recovery.
4. **RAM-only boundary.** Application buffers are RAM-only, but host swap/hibernation/core collectors, external platform/browser copies and infrastructure logs need their own policies. macOS log rotation and host memory controls are operator-managed. Web byte accounting intentionally excludes Python/native decoded memory; an OOM kill can still occur if host budgets are undersized. Force-killed processes lose queues and images.
5. **Operational follow-up.** Add structured destination-success metrics and alerting for persistent channel failures, investigate production parser drift, review constrained dependency updates and deprecation warnings, and consider a carefully tested CSP/edge admission policy. Do not expose an unguarded feed path merely to restore the terminal dashboard when Turnstile is enabled.
